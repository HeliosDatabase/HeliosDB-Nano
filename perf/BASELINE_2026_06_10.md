This is the reference point for the roadmap-item A/B protocol (ROADMAP_FASTEST_ACID_HTAP.md).
Every roadmap item is compared against this file (or the most recent successor baseline)
in two groups: **direct** categories (what the item claims to improve) and **indirect**
categories (everything else, as a regression gate). Documented run noise on this harness
is ±10-20%; treat <20% deltas on analytics workloads (20 ops/measurement) as noise and
rerun before concluding.

## Comparison protocol

1. Baseline runs live in `perf/baseline_runs/`; post-change runs go to
   `perf/<item>_runs/`. Same N/M, same mode flags, same host, sequential runs only.
2. mem suite ×2 + disk suite ×1 + cache-concurrency + any item-specific bench.
3. Direct categories must improve (or hit the item's stated target); indirect
   categories must stay within noise (>20% regression = investigate before merge).
4. Per-item report: `perf/<item>.md` with the before/after table, in the style of
   perf/P0_*.md. Follow the heliosdb-nano-merge-validation phases before merging.

### R0.1 targets against this baseline

- **Correctness (primary):** wire connections get isolated transactions — no
  cross-connection bleed; PG-wire in-txn SELECT gains read-your-writes
  (query_with_columns currently never attaches the txn to the executor).
- session_txn_cycle(1T): ≥ ~40k txn/s (close the gap to global_txn_cycle by
  enabling the literal txn fast-insert path for session transactions).
- session_txn_cycle(16T): meaningfully above 1T (target ≥2× 1T).
- autocommit_insert_with_open_session_txn: back to ≥ ~80k ops/s under default
  config (TT-aware INSERT fast-path gate; UPDATE/DELETE stay conservative).
- Indirect: mem/disk TPS suite and cache-concurrency within noise.
