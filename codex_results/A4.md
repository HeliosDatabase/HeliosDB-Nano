# A4 Result - binary TIMESTAMP and UUID parameter inputs rejected

## Verdict

**REAL BUG - fixed.** Binary PostgreSQL extended-protocol parameters for TIMESTAMP and UUID decoded as `Value::Bytes`, so later casts rejected valid psycopg3 binary-mode inputs.

Baseline branch: `fix/codex-v334-a4` from consolidated final/main `6d46a67`.

## Baseline

Command:

```text
cargo fmt --check && cargo test --test postgres_extended_protocol_tests test_decode_binary_ -- --nocapture
```

Result before the fix:

- `test_decode_binary_timestamp_parameter` failed: OID `1114` decoded to `Value::Bytes([0, 0, 0, 20, 29, 234, 54, 135])` instead of `Value::Timestamp(2000-01-02T00:00:01.234567Z)`.
- `test_decode_binary_uuid_parameter` failed: OID `2950` decoded to the 16 raw bytes instead of `Value::Uuid(12345678-1234-5678-9abc-def012345678)`.
- Existing primitive binary decoder coverage still passed.

## Root Cause

`src/protocol/postgres/prepared.rs` `decode_binary_parameter` had binary arms for primitive numeric/text OIDs, then fell through to `Value::Bytes` for all other binary parameter OIDs. PostgreSQL binary TIMESTAMP (`1114`) is an 8-byte big-endian signed microsecond offset from the PostgreSQL epoch (`2000-01-01T00:00:00Z`), and UUID (`2950`) is exactly 16 RFC 4122 bytes.

## Fix

Added decoder arms before the catch-all:

- `1114 | 1184`: decode TIMESTAMP/TIMESTAMPTZ as exactly 8 bytes, convert PostgreSQL-epoch microseconds to Unix-epoch microseconds with checked addition, then build `Value::Timestamp` via `chrono::DateTime::from_timestamp_micros`.
- `2950`: decode UUID as exactly 16 bytes into `Value::Uuid(uuid::Uuid::from_bytes(...))`.

Malformed short and overlong fixed-width payloads now return protocol errors, and extreme timestamp offsets return range errors instead of panicking.
