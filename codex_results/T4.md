# T4 Result - CREATE BRANCH AS OF NOW records branch names

## Verdict

**Already fixed - confirmed.** Regression test only; no source change.

Baseline branch: `fix/codex-v334-t4` from consolidated final/main `4546be5`.

## Checklist Claim

After `CREATE BRANCH b AS OF NOW`, `SHOW BRANCHES` returns a row with an empty branch name because the branch name is not written into branch metadata.

## Baseline Result

The checklist's exact public path is green on the current consolidated baseline:

- `CREATE BRANCH t4_short AS OF NOW`
- `SHOW BRANCHES`
- `SELECT * FROM pg_database_branches()`

Both listing paths include the expected branch name and no empty-name row.

## Root Cause Assessment

No current source bug was found for the T4 acceptance criteria.

The public parser returns the parsed branch name to `BranchingParser::parse_create_branch`, the logical plan carries `branch_name`, `handle_create_branch` passes `branch_name` into `storage.create_branch_at_snapshot`, and `BranchMetadata { name: name.to_string(), ... }` stores the name consumed by `SHOW BRANCHES`.

## Regression Coverage

- Supported `AS OF TIMESTAMP '<timestamp>'` public SQL path with a registered snapshot.
- Stress/no-regression loop creating 50 short-form `AS OF NOW` branches and listing them; no empty names.
