# A15 Result - Binary Int4 Extended Results In Transactions

## Verdict

Positive. Commit eligible.

The regression is present before the fix: an extended-query Bind inside an explicit transaction can request binary int4 results, but the server describes the portal as text and sends the text payload `1` (`[49]`) instead of the four-byte network-endian int4 payload (`[0, 0, 0, 1]`). This matches asyncpg's observed binary decoder failure shape: requested 4 bytes, only 1 byte available.

## Scope

- Source: `src/protocol/postgres/handler.rs`
- Source: `src/protocol/postgres/handler_extended.rs`
- Regression: `tests/a15_postgres_binary_int4_transaction.rs`
- Regression ported from Claude: `tests/v334_a15_binary_int4.rs`
- No planner, executor, storage, transaction-state, or auth changes.

## Baseline

- Test: `cargo test --test a15_postgres_binary_int4_transaction -- --nocapture`
- Result before fix: FAIL, 0 passed / 2 failed.
- Regression failure:
  - `Describe Portal` reported result `format_code = 0` after Bind requested binary result format `1`.
  - `DataRow` returned one text byte `[49]` for integer `1` instead of binary int4 bytes `[0, 0, 0, 1]`.
- Baseline performance: unavailable as a useful throughput number because the stress test failed on the first binary result assertion.
- Faithful asyncpg note:
  - A throwaway asyncpg harness under `/tmp/hdb-a15-venv` connected, but hit pre-existing asyncpg type-introspection recursion before reaching the A15 table-query repro.
  - To isolate A15, the committed regression uses raw PostgreSQL wire frames matching the asyncpg-relevant shape: explicit `BEGIN`, Parse, Bind with binary int4 parameter, binary int4 result requested, Describe Portal, Execute, Sync.

## Fix

- Added result-format-aware RowDescription helpers for portal Describe.
- Added result-format-aware DataRow encoding for extended Execute.
- Honored binary result format for supported scalar types:
  - `bool`, `int2`, `int4`, `int8`, `float4`, `float8`, `bytea`, `text`, `varchar`, `uuid`
- Encoded `int4` as PostgreSQL binary wire format: four-byte big-endian signed integer.
- Kept unsupported binary result types on text RowDescription format instead of falsely labeling text bytes as binary.
- Routed catalog SELECT, ordinary SELECT, and DML `RETURNING` rows through the portal result-format encoder.

## After

- Test: `cargo test --test a15_postgres_binary_int4_transaction -- --nocapture`
- Result after fix: PASS, 2 passed / 0 failed.
- Stress/perf: 100 binary int4 extended SELECTs inside one transaction completed in `74.854905ms`.
- Regression behavior:
  - Binary int4 parameter `1` matches the row inside an explicit transaction.
  - `Describe Portal` reports type OID `23` and format code `1`.
  - `DataRow` carries `[0, 0, 0, 1]`.
  - `ReadyForQuery` remains in transaction state `T` until COMMIT/ROLLBACK.
