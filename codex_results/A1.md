# A1 Result - ANY Parameter Arrays

## Verdict

Positive. Commit eligible.

The regression is present on final-main `e32d58d`: `WHERE col = ANY($1)` with `$1` bound to `Value::Array(...)` silently returns zero rows. The same false result also happens for `ANY(ARRAY[...])`. Existing `IN (...)` predicates and the older casted PostgreSQL array literal shape work.

## Scope

- Source: `src/sql/planner.rs`
- Source: `src/sql/evaluator.rs`
- Regression: `tests/v334_a1_any_param_array.rs`
- No storage, protocol, transaction, or catalog changes.

## Baseline

- Branch: `fix/codex-v334-a1` from final-main `e32d58d` (A8 + A14 + A15 + A5).
- Test: `cargo test --test v334_a1_any_param_array -- --nocapture`
- Result before fix: FAIL, 0 passed / 3 failed.
- Failed surfaces:
  - `name = ANY($1)` with `$1 = ARRAY['alpha','beta']` returned `[]` instead of `['alpha','beta']`.
  - `name = ANY(ARRAY['alpha','beta'])` returned `[]`.
  - integer count stress returned `0` instead of `20` for each parameter-array query.
- Baseline performance: unavailable because the stress assertion failed on the first query.

## Fix

- Kept the existing literal cast support for `ANY('{...}'::type[])`.
- Added planner support for SQL `ARRAY[...]` by rewriting it to the existing `InList` representation.
- Added planner support for runtime parameter arrays by producing an `InList` with an internal `__hdb_any_array` marker around the parameter expression.
- Added evaluator support for that internal marker inside `InList`: after parameter binding, `Value::Array` elements are compared one by one with SQL NULL behavior preserved.
- Unsupported column/subquery array ANY forms still fall back to the prior constant-false behavior; full array-column ANY support remains outside A1.

## After

- Test: `cargo test --test v334_a1_any_param_array -- --nocapture`
- Result after fix: PASS, 4 passed / 0 failed.
- Stress/perf: 10 parameter-array ANY count queries completed in `10.664217ms`.
- Regression behavior:
  - `WHERE name = ANY($1)` matches the same rows as `WHERE name IN (...)`.
  - `WHERE name = ANY($1::text[])` also matches.
  - `WHERE name = ANY(ARRAY['alpha','beta'])` matches.
  - Existing cast literal shape `ANY('{alpha,beta}'::text[])` remains covered.
  - Plain `WHERE name IN ($1)` with `$1` as an array parameter is not rewritten as `ANY($1)`.
