# A7 Result - UNIQUE TEXT Shared-Prefix False Duplicate

## Verdict

Positive. Commit eligible.

A7 is a real bug, but not in `ArtIndexManager::encode_key`: TEXT values are encoded with full `s.as_bytes()`. The failure is lower in the ART path-compression logic. A two-row test with shared long prefixes passes, but many distinct keys with the same long prefix can be routed through a compressed prefix without comparing the hidden prefix tail, causing false UNIQUE duplicates.

## Root Cause

`ArtIndexManager::encode_key` already uses the full string bytes, but ART nodes store only the first `MAX_PREFIX_LEN` bytes of a compressed prefix while preserving the full `prefix_len`.

During insert, the old code compared only the stored prefix bytes and then skipped the full `prefix_len`. If two keys differed after the stored prefix but before `prefix_len`, insertion could route the new key to the wrong child. With a UNIQUE index and many long shared-prefix TEXT keys, that produced a false duplicate.

## Fix

- Added full compressed-prefix comparison for ART insertion by comparing the hidden prefix tail against a descendant leaf key.
- Updated split logic to recover hidden prefix bytes from that descendant leaf when splitting a node after `MAX_PREFIX_LEN`.
- Reused the same full-prefix check in `get`, `get_all`, `remove`, and `remove_value` so reads/deletes do not trust only the stored prefix bytes.
- Left `encode_key` unchanged; it already encodes full TEXT bytes.
