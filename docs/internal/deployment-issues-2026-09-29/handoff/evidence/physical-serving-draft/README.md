API: `ServingGenerations::new(parent:PathBuf,config:Config,limits:TransferLimits,max_resident:usize)->Result<Arc<Self>,String>`; `lease()->Option<ServingLease>`; `last_error()->Option<String>`; `close_and_join()` and `reap_retired()` return Result<(),String>. Lease is Clone and exposes borrowed database(), history(), source_sequence(), report(), image_bytes(). Internal PG wiring can use database_arc() only while retaining the lease through DB/catalog/session use. No listener/readiness is added.

ReceiverOptions adds `serving:Option<Arc<ServingGenerations>>`, refused without require_committed. Before any generation copy a shared resident/build permit is reserved; the reservation moves INTO the single receiver worker command and returns in PreparedGeneration with image declared before reservation, so cancellation/unobserved replies cannot release capacity before copy and directory destruction finish. The command checks private receiver owner+entire durable cursor before and after copying. It creates a raw checkpoint, copies bounded files into distinct inodes with hashes and nofollow regular-file checks, verifies the copied durable cursor, and removes the temporary hardlink checkpoint before acknowledging/resuming apply. Independent image failure retains the old serving generation and raw state; actual receiver poison still fails subsequent apply.

One retained std thread performs strict EmbeddedDatabase::open_physical_snapshot and swaps a fully hydrated Arc generation under a short lock, requiring same history and strictly newer source sequence. Existing leases remain coherent; resident capacity counts active/building/retired/escaped references. Full capacity skips image refresh while raw Follow continues. Strict hydration errors are recorded and leave current generation unchanged. It does not start GC/auto-refresh/background writers.

Reclamation is separate from publication/request drop. A retired record owns EmbeddedDatabase Arc, raw RocksDB sentinel, TempDir and resident permit. The collector atomically Arc::try_unwrap's the Embedded owner and raw sentinel before dropping RocksDB then deleting the directory; a count-then-delete race with Weak upgrades is avoided. Failed unwrap retains files and budget. close_and_join stops publication, drops queued jobs, joins the actual worker and reports pinned resources. A later reap_retired can clean after escaped refs release. Unexpected publisher teardown behind escaping references deliberately retains its private directory and logs an error rather than deleting beneath a live DB. Caller shutdown must stop/join PG request tasks and release leases before expecting complete cleanup.

Current API does not prohibit callers from retaining underlying DB/storage Arcs; it makes that safe/bounded while the publisher remains alive. Config and copy limits bound each generation but not synchronous OS IO latency. No hard cancellation deadline is claimed. The source admitted-operation contract, PG readonly/session migration, prepared-plan/result-shape validation, readiness publication and performance/runtime evidence remain outstanding. Existing raw CLI uses require_committed:false and serving:None. The parent owns PG generation integration separately.

Tests exercise old/new SQL request leases across two publications, resident-budget backpressure while raw Follow advances, raw stage reopen with serving leases alive, escaped raw-Arc directory retention then cleanup; failed strict routine hydration preserving old SQL reads while raw progress continues; and Weak upgrade refusal after atomic retirement. They are authored and UNRUN.

Final cleanup-order revision: hydrate retains PreparedGeneration intact across all fallible validation/open calls, then destructures only after success. On error, copied image cleanup precedes reservation/capacity release. This extends the same owned-result invariant used by the copy command.

Final accounting revision: after strict hydration, a census includes every retained file (including marker and RocksDB LOG) and checks max_files/max_file_bytes/max_total_bytes before publication; image_bytes reports that census. Generation sentinel/retirement ownership is established before this fallible step, so failure safely queues DB and directory cleanup without early resident-budget release. The census bounds the image at publication; this is not an OS disk quota against future diagnostic log growth.
