# Spec P2.2 — remote replication over TLS; resumable snapshot download; fireproof odds and ends

Parent: `PHYSICAL_STANDBY_REPLICATION.md` §D5, §D7. Sprinter `86d44281eabd`. After P2.1.

Value: the physical channel is loopback-only (physical_wire.rs `bind_loopback`/`connect_loopback`,
main.rs accept filter, receiver validate, config). Proxy's lab and every real deployment need a
standby on another host. A snapshot download that dies midway restarts from zero today.

## 1. TLS on the single replication port
- Server: `[replication] tls = { cert, key, ca?, require_client_cert = false }`; defaults to the
  `[server] tls_*` pair when unset and `[server] tls_enabled`; a non-loopback listener without TLS
  is refused unless `allow_insecure_remote = true` (keep the bearer token as the second factor in
  all cases). Reuse `tls_provider.rs` (`pq_capable_provider`, `load_cert_and_key`, `load_ca_certs`)
  and `postgres/ssl.rs::load_tls_config` (client-cert verification for mTLS); `tls_stream.rs`
  `SecureConnection` for the framed stream.
- Client (standby): `[replication] primary_tls = { ca?, verify_hostname = true, client_cert?, client_key? }`;
  `--primary-ca`; system roots when `ca` is unset; `verify_hostname = false` only with
  `allow_insecure_remote`.
- Remove the loopback checks (physical_wire.rs ~489-494, ~936-944; main.rs ~5224, ~5305;
  physical_receiver.rs ~79-89; config.rs ~3250-3256) and replace them with "TLS or loopback or
  explicit insecure opt-in".
- The export directory census and the stage file census are unchanged.

## 2. Resumable snapshot download (`checkpoint_transfer.rs`)
- `ChunkRequest { file, offset }` already exists per chunk; make the receiver persist progress in
  the staging dir (`NANO-PHYSICAL-PARTIAL.json`: snapshot_id, manifest sha, per-file bytes done)
  and, on restart with the same manifest/snapshot_id still exported by the primary, continue from
  the recorded offsets (each completed file verified by its SHA-256 before being counted). A
  different manifest → start over (delete the partial). The primary keeps an export lease alive
  for `[replication.physical] export_lease_secs` (default 3600) after the last chunk request.
- The receiver's download loop reconnects with backoff on transport errors instead of `?`-failing
  (physical_receiver.rs ~53-56 "never adopted" rule becomes "adopted when the partial file matches").
- `ReceiverStart::Resume` for the tail is unchanged.

## 3. Fireproof items (§D5) not yet done
- `--dump-on-shutdown` on a standby: refused (P1.3 did this — verify, keep).
- `enable_lockfree_ingestion` refused when `role = primary` (any replication role) with a message
  explaining it bypasses the logical WAL/MVCC/indexes; the `data/lockfree_wal` path moves under
  the data dir for the remaining embedded use (Sprinter `96e5a8cfa254` item 3).
- `replication_wal/` creation removed (P2.1 covers it — verify).
- HNSW `hnsw_snapshots/` files: add the dump SHA-256 to the `vecsnap:` sidecar and refuse a
  mismatching file at hydration (the full move into RocksDB stays P5).
- Encryption key rotation while a standby is attached: refuse `rotate` unless every registered
  standby reports the new key-check id in its heartbeat (capability flag); document.

## 4. Tests
- `tests/physical_standby_tls.rs`: pair across two network namespaces or two loopback aliases
  with TLS (self-signed CA generated by the test; reuse the cert helpers used by the PG TLS tests),
  mTLS variant, wrong CA refused, plaintext remote refused without the opt-in, token still required.
- `tests/physical_snapshot_resume.rs`: kill the receiver at 30 % / 70 % of a multi-file download
  (make the primary big enough for ≥ 3 SST files), restart, assert bytes re-downloaded < 1 chunk per
  file and the final census/digest equal; manifest change → full restart.
- Fixture `nano-physical-pair.sh --tls` option generating a throwaway CA; Proxy's template gets
  the PG ports unchanged (TLS is on the replication port only).

## Constraints
No cargo/git; read before edit; match style; never weaken the token or census checks. Report
files, the config table, how the receiver decides "resume vs restart", tests red/green, commands.
